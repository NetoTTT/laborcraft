# 09 — UI e comandos

Escopo: como a interface do LaborCraft é construída, quais componentes existem e por que toda ação da UI também existe como comando.

## Regra de arquitetura: command-first

1. Toda ação que altera estado tem um comando em `LaborCraftCommands`.
2. A UI **nunca** altera estado diretamente: ela compõe e envia o comando equivalente.
3. O servidor valida permissão e dono; a UI não é fonte de verdade.
4. O comando e a UI chamam a mesma lógica de servidor, então não há duas implementações.

Fluxo atual:

```
/laborcraft ui
  -> comando de servidor (sem permissão)
  -> OpenAdminPayload (clientbound)
  -> cliente agenda setScreenAndShow(LaborCraftAdminScreen)

/laborcraft config
  -> comando de servidor (sem permissão)
  -> OpenConfigPayload (clientbound)
  -> cliente agenda setScreenAndShow(LaborCraftConfigScreen)

/laborcraft language pt_br
  -> comando de servidor (sem permissão)
  -> SetLanguagePayload (clientbound)
  -> cliente altera options.languageCode, salva e recarrega recursos

LcButton
  -> LaborCraftUiActions.run(LaborCraftCommands.ADMIN_RELOAD)
  -> ClientPacketListener.sendCommand("laborcraft admin reload")
  -> CommandSourceStack (permissão COMMANDS_GAMEMASTER)
  -> LaborCraftCommands.reload(...)
  -> feedback no chat
```

Abrir a UI é um comando de **servidor** que envia um payload; não existe comando de cliente com o mesmo root. Isso é deliberado: um root de cliente chamado `laborcraft` intercepta todos os `/laborcraft ...` e impede os subcomandos de servidor (`admin`) de executar. O payload também evita a tela ser fechada pelo chat na mesma tick.

Os nomes ficam em constantes (`LaborCraftCommands.ADMIN_RELOAD`) para a UI e os testes não duplicarem strings.

## API de GUI do Minecraft 26.3

O 26.3 usa **extração de render state**, não o antigo `render(GuiGraphics, ...)`:

- `Renderable.extractRenderState(GuiGraphicsExtractor, mouseX, mouseY, delta)`.
- `Screen.extractBackground(...)` desenha o fundo antes dos widgets; `Screen.extractRenderState(...)` extrai os widgets.
- `AbstractWidget.extractWidgetRenderState(...)` é o ponto de desenho de um widget.
- `GuiGraphicsExtractor` oferece `fill`, `outline`, `text`, `centeredText`, `textWithWordWrap`, `blit`, `blitSprite`, `item`, `setTooltipForNextFrame`.
- Input usa records: `KeyEvent`, `MouseButtonEvent`, `InputWithModifiers`.
- Layouts continuam: `GridLayout`, `LinearLayout`, `FrameLayout`.
- `Button.builder(...).bounds(...).tooltip(...)` continua sendo o caminho mais curto para botões vanilla.
- Comandos de cliente Fabric (`ClientCommands`) **não** podem compartilhar o root com comandos de servidor: o dispatcher cliente intercepta o root inteiro. Para abrir tela, use comando de servidor + payload (como em `OpenAdminPayload`).

Referências consultadas (out/2026): código-fonte do ModMenu 26.3 (MIT) para o padrão de `extractRenderState`/tooltips e da API do Fabric. Nenhuma lib de GUI foi adicionada.

| Componente | Papel |
| --- | --- |

| `LcRender` | painel com sombra/borda, borda e divisor |
| `LcTooltips` | tooltip com título, descrição e linha do comando em dourado |

| `LaborCraftWorkerScreen` | base das telas de trabalhador: identidade, retrato, nome, emprego, saúde, estado e botão fechar |
| `LaborCraftHiringScreen` | contratação de um trabalhador vago, com termos e ação de contratar |
| `LaborCraftEmployeeScreen` | informações do empregado, emprego atual, atribuição e dispensa |

| `LcPagination` | modelo genérico de páginas: itens, tamanho da página, anterior/próxima e índice atual |
| `LcItemGrid` | grade de itens configurável (colunas, linhas, célula, espaçamento), com ícone, quantidade total, hover/tooltip e clique |
| `LaborCraftItemTestScreen` | tela de teste com 50 itens em grade 10x5, hover e clique |
| `LaborCraftItemActionScreen` | base da tela de opções de um item; recebe as opções de fora, quantidade/estoque e preserva a página de retorno |

Exemplo de uso:

```java
LcButton button = new LcButton(x, y, 200, 26, label, LcButton.Variant.PRIMARY,
        () -> LaborCraftUiActions.run(LaborCraftCommands.ADMIN_RELOAD));
button.tip(LcTooltips.of(title, description, "/" + LaborCraftCommands.ADMIN_RELOAD));
addRenderableWidget(button);
```

- Navegação, paginação e seletores usam o som padrão de botão (`UI_BUTTON_CLICK`).
- Ações de item (pegar, comprar, equipar, usar) usam `SoundEvents.EXPERIENCE_ORB_PICKUP` via `LcButton.clickSound(...)`. Em `LaborCraftItemActionScreen.Option`, o padrão é esse som; passe `null` como sexto argumento para ações neutras/negativas, como “Deixar”.

## Como adicionar uma nova ação

1. Registrar o comando em `LaborCraftCommands` (com a permissão correta).
2. Expor uma constante pública com o comando completo.
3. Criar o `LcButton` na tela chamando `LaborCraftUiActions.run(constante)`.
4. Tooltip: título, descrição e comando.
5. Adicionar chaves em `en_us.json` e `pt_br.json`.
6. Atualizar `docs/09-UI.md` se o componente for novo.

Para abrir uma nova tela, registre um comando de servidor que envia um payload clientbound e registre o receiver no entrypoint de cliente. Não registre um root de cliente igual ao do servidor.

## Navegação e idioma

- A tela Admin tem o botão **Config** no cabeçalho: envia `/laborcraft config`.
- A tela Config tem **Voltar** (`/laborcraft ui`) e **Fechar**.
- O seletor de idioma tem dois botões, **Português (Brasil)** (`/laborcraft language pt_br`) e **English (US)** (`/laborcraft language en_us`). O botão do idioma atual fica marcado.
- O comando de idioma é de servidor, mas a preferência é do cliente: o servidor apenas envia `SetLanguagePayload` para quem executou.
- O cliente aplica `LanguageManager.setSelected` + `options.languageCode`, salva `options.txt` e chama `reloadResourcePacks()`. Se a tela Config estiver aberta, ela é recriada para refletir a seleção.
- A preferência não é sincronizada entre jogadores nem salva no servidor; cada cliente tem a sua.

## Paginação e grade de itens (teste)

Fluxo:

```
/laborcraft test items
  -> comando de servidor (sem permissão)
  -> OpenItemTestPayload (clientbound)
  -> LaborCraftItemTestScreen(page 0)

clique em um item
  -> LaborCraftItemActionScreen(item, tipo, opções, voltar para a página)
  -> Pegar / Deixar / ação específica do tipo
  -> volta para LaborCraftItemTestScreen na mesma página
```

- `LcPagination<T>` não conhece GUI: recebe uma lista e um `pageSize`, expõe `pageItems()`, `pageCount()`, `previous()`, `next()` e `setPage()`. Pode ser reutilizado por contratos, trabalhadores, loja etc.
- `LcItemGrid<T>` recebe uma função `T -> ItemStack` e uma função `T -> long` para a quantidade de domínio. Desenha slots vazios e preenchidos, usa o ícone com contagem 1 e desenha o total por cima (`itemDecorations`), inclusive acima de 64. No hover, mostra o tooltip completo do `ItemStack` mais o total exato e a quebra em pilhas.
- Quantidades grandes usam sufixos compactos no slot (`2k`, `3M`) e o valor exato no tooltip. A representação não cria vários slots nem depende do limite de 64: cada linha da grade é um tipo de item com o estoque total.
- A grade do teste é 10x5 (50 slots por página), com 50 itens. As setas ficam desabilitadas quando não há outra página.
- `LaborCraftItemActionScreen.Option` tem `label`, `description`, `command` (opcional), `action` e um som opcional. O teste usa ações locais; uma tela real deve preencher `command` e chamar `LaborCraftUiActions.run(...)` no handler, mantendo o comando como fonte de verdade.
- O seletor de quantidade usa `-`, `+` e `Tudo`, limitado ao estoque total (`long`), não ao tamanho da pilha. `Pegar` confirma a quantidade e volta para a lista; `Deixar` volta sem pegar.
- Ações de item tocam o som de coleta de XP; `Deixar` e botões de navegação mantêm o clique padrão.
- As opções mudam por tipo (`Comida`, `Ferramenta`, `Bloco`, `Material`) e a tela base mostra no máximo 3 opções.
- **Exceção deliberada:** esta tela é um harness de UI. As ações são locais, mostram uma mensagem no chat e não alteram inventário/mundo. Não há comando de `take` para itens de teste.

## Jogadores online

```
/laborcraft players
  -> comando de servidor (sem permissão)
  -> OpenPlayersPayload (clientbound)
  -> LaborCraftPlayersScreen
```

- A tela lê `ClientPacketListener.getOnlinePlayers()` no cliente; o servidor só autoriza a abertura.
- Exibe rosto (`PlayerFaceExtractor`), nick da tab list, latência e destaca o jogador local; o jogador local aparece primeiro.
- Seis jogadores por página, com anterior/próxima, contador, **Voltar** para o Admin e **Fechar**.
- O botão **Jogadores online** na tela Admin envia `/laborcraft players`.

## Trabalhador: loja de contratação e empregado

```
/laborcraft hire
  -> OpenHiringPayload(ofertas, saldo, ativos, contratos, limite)
  -> LaborCraftHiringScreen

Comprar
  -> /laborcraft worker buy <oferta>
  -> servidor valida limite, saldo e espaço na mochila
  -> entrega Contrato de Trabalhador
  -> OpenHiringPayload atualizado; o botão desabilita no limite

Usar o Contrato de Trabalhador
  -> servidor valida o limite de trabalhadores ativos
  -> spawna o trabalhador já com dono
  -> OpenWorkerPayload
  -> LaborCraftEmployeeScreen

Fazendeiro
  -> /laborcraft worker assign <uuid> laborcraft:farmer
  -> servidor valida dono e emprego
  -> payload atualizado; a tela continua aberta

Dispensar (duas confirmações)
  -> /laborcraft worker dismiss <uuid>
  -> servidor transforma o trabalhador em contrato e remove a entidade
  -> contrato volta para a mochila (vinculado ou negociável)
```

- A loja é pública e abre por `/laborcraft hire`; o servidor calcula preço, saldo, trabalhadores ativos, contratos não usados e limite.
- `worker.maxWorkersPerPlayer` conta trabalhadores ativos **e** contratos ainda na mochila; ao atingir o limite, o botão **Comprar** fica desabilitado e o comando também recusa a compra.
- O contrato é um item próprio (`laborcraft:worker_contract`), guarda o UUID do comprador no componente `laborcraft:contract_owner` e só pode ser usado por ele; ao ser usado, o trabalhador nasce com o UUID do jogador e a tela de Empregado abre.
- O servidor só abre a tela de Empregado para o dono; outros jogadores recebem uma mensagem no chat. Trabalhador sem vínculo (spawn de admin) não abre a loja.
- O payload carrega um retrato do momento: nome, emprego, estado, tarefa, vida, fome e humor, além da casa atual e da lista de casas do jogador. A UI não consulta nem altera a entidade.
- A tela **Empregado** tem abas **Resumo / Emprego / Casa**: Emprego lista os cargos e Casa lista as casas por nome, camas livres e validade (atribuir/liberar). O clique numa casa manda o comando com a cama livre específica.
- O registro da casa usa um modal (`LaborCraftHomeRegisterScreen`): agachar + clique direito na cama envia um preview, o jogador confere os dados, digita o nome e confirma. O claim só acontece no confirmar. Se a casa já for sua, o mesmo modal oferece **Renomear** e **Desvincular casa** (dois cliques); desvincular libera o cômodo para outro jogador.
- `buy`, `assign` e `dismiss` são comandos disponíveis a qualquer jogador, mas o executor valida limite/dono. `spawn`/`remove` continuam restritos a gamemaster.
- A dispensa usa confirmação em dois cliques no próprio botão; nenhum estado muda no primeiro clique.
- Para testar a compra sem economia externa: `/laborcraft admin set balance <valor>` define o saldo no provedor ativo.

## Prompt de valor no chat

`LcValuePrompt` é o componente para ações que precisam de um valor:

```java
LcValuePrompt.integer(rotulo, "laborcraft admin set wage ", 0, 100000)
        .quick("0", "0")
        .quick("24", "24")
        .ask();

LcValuePrompt.choice(rotulo, "laborcraft admin set provider ", ids).ask();

LcValuePrompt.text(rotulo, "laborcraft admin set label ", 64).ask();
```

- `ask()` adiciona uma mensagem local no chat e abre o chat vazio; o jogador digita **apenas o valor** e Enter.
- O cliente intercepta a mensagem (`ClientSendMessageEvents.ALLOW_CHAT`), valida e envia o comando completo; a mensagem crua não vai para o chat.
- `Esc` fecha o chat e cancela; digitar `cancel`/`cancelar` cancela e volta para a UI; `[Cancelar]` executa `/laborcraft ui`.
- Valores rápidos e opções usam `SuggestCommand` com **apenas o valor**: o clique preenche o campo e o jogador confirma com Enter.
- A validação real continua no servidor: `IntegerArgumentType.integer(0, 100000)` rejeita negativos antes de executar; ids de provedor usam argumento greedy e conferência com mensagem de erro amigável. Para texto, o comando deve validar vazio/tamanho no executor.
- Acessibilidade: a mensagem imprime a sintaxe completa e todos os botões têm comando equivalente. Nada depende exclusivamente de clique; o jogador pode digitar o comando inteiro (nesse caso o prompt é descartado).

Exemplo atual no Admin: **Base wage** (`set wage <int>`) e **Currency provider** (`set provider <id>`). O tipo texto está pronto no componente para a próxima ação que precisar.

## Permissões

A tela pode ser aberta por qualquer jogador com `/laborcraft ui`, mas cada ação é validada no servidor. Hoje `reload` e `status` exigem `COMMANDS_GAMEMASTER`; se faltar permissão, o servidor responde com erro no chat. O tooltip informa o requisito.
## Limitações atuais

- Existem as telas Admin, Config, teste de itens, ação de item, jogadores online, Loja de contratação, Empregado e o modal de registro de casa; o Empregado usa abas **Resumo / Emprego / Casa**, as demais não têm abas; scroll próprio na loja, no perfil e nas abas do Empregado.
- A grade de teste é fixa em 10x5 e a tela de ação mostra no máximo 3 opções; ainda não há scroll para listas maiores.
- A lista de jogadores é um retrato do momento da abertura; não se atualiza sozinha enquanto a tela está aberta.
- Ações da tela de teste são locais (não alteram inventário).
- O idioma é preferência local do cliente (`pt_br`/`en_us`); não há seletor para os demais idiomas do jogo.
- Feedback é texto no chat; ainda não há payload estruturado de resposta.
- Sem integração com aba do criativo.
- O item/bloco do posto ainda não usa a UI.
- Valores correntes de config não são enviados pelo servidor ao cliente; o prompt mostra apenas faixa/opções.

## Roadmap de UI

1. Abas e evolução do componente de scroll.
2. Tela de contrato completa: salário, período, área, casa e expediente.
3. Feedback estruturado (payload) mantendo o comando como fonte de verdade.
4. Editor de skin/nome do trabalhador.
5. Lista paginada de trabalhadores do jogador.

## Atualização: loja rolável e perfil

- `LcScrollList` é o componente reutilizável de lista com viewport recortado, roda do mouse, barra de posição e clique por linha.
- A loja `/laborcraft hire` usa `OpenHiringPayload` com uma lista de ofertas; cada oferta tem id, emprego, nome, descrição, boost opcional, preço e manutenção. O rodapé é rolável e o botão **Comprar** envia `/laborcraft worker buy <oferta>`.
- O perfil abre por `/laborcraft profile` (`OpenProfilePayload`) e mostra dinheiro, empregados/limite e uma lista rolável com nome, emprego, tarefa, vida, fome e humor.
- `LcScrollList` não usa a Creative Inventory; o comportamento é reproduzido com scissor, offset e barra próprios.

## Destaque no mundo (baús, trabalhadores e alvos futuros)

- `WorldHighlightManager` desenha um wireframe de partículas por 10 s:
  - **bloco**: caixa fixa em volta do bloco (baú);
  - **entidade**: usa o bounding box atual a cada tick, então acompanha o trabalhador em movimento.
- `TargetIndicatorHud` (HUD element) mostra ícone, seta e distância quando o alvo está fora da câmera; lê o mesmo alvo/ícone do manager.
- Aba **Baús** do Posto: botão de olho por baú.
- Abas **Trabalho** do Posto e **Perfil**: botão de olho por trabalhador; fecha a tela, destaca a entidade e avisa se ela não estiver carregada por perto.
- Ícone do HUD vem de `WorldHighlightManager.icon()` (baú para baús, olho do End para trabalhadores).
- Reutilizável para alvos futuros (pedreiro, minerador).
